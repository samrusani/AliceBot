## Option A truth boundary

True redaction destroys governed content copies in the coupled memory/project-
update graph but does not undo an accepted update already represented in
`projects.current_state`. It intentionally does not modify source or source-
chunk evidence because either may support other memories. It also cannot erase
upstream source systems, prior exports, database backups, logs outside the
governed schema, or artifacts a user copied elsewhere. Those are explicit
operator obligations, not hidden implementation claims.

PostgreSQL owns generated artifacts and quality ratings, so its response may
report positive artifact/rating counts. SQLite has no generated-artifact or
quality-rating repository; it truthfully returns zero for those two fields
while providing parity for memory, revision, event, and memory provenance
redaction. This is a store-boundary fact, not an inferred success.

## Release boundary

At package-input freeze, local green evidence did not approve publication. The
final `BUILD_REPORT.md` is authoritative for package/receipt evidence, and the
reviewer-authored `REVIEW_REPORT.md` is authoritative for independent approval.
After reviewer approval, the only remaining gates are the final committed SHA,
required-check/MainProtect and CodeQL readback, real-provider semantic
attestation, tag/release identity, GitHub Release, and PyPI publication/
verification.
