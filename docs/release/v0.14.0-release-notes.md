# Alice v0.14.0 Release Notes

**A deployable, hardened single-tenant contract, proven on a real host.**

`v0.14.0` is the Phase 5 enterprise-track release. Its center of gravity is
operational: a documented single-tenant deployment shape that has now been
executed end to end on a real public host, with the failures that execution
surfaced fixed in the same release. Memory behavior, retrieval ranking, and the
agent API surface are unchanged.

## Single-tenant self-hosted deployment, exercised for real

The supported deployment shape is one owner, one host: the Alice API and
prebuilt web console bound to loopback, Caddy as the only public process
terminating public TLS and requiring a client certificate from an
operator-controlled CA, PostgreSQL 16 with pgvector over certificate-verified
TLS, and distinct migration and runtime database roles.

This contract is no longer only a document. It was deployed on a real cloud VM
with public DNS and a publicly trusted server certificate, and the owner
recorded a sanitized deployment receipt covering 29 checks: migration,
loopback and external health, keyless rejection and authenticated access over
HTTPS, mutual-TLS rejection of absent and untrusted client certificates,
security headers, route-boundary probes proving `/v1` and legacy `/v0` are not
publicly reachable, runtime role least privilege, scheduler state, encrypted
off-host backup, and a restore of a real encrypted backup into a disposable
database. The receipt contains no hostnames, addresses, credentials, or paths.

## Least privilege that actually holds

The first real-host execution found five defects in the deployment guide, all
fixed here:

- Workspace bootstrap requires a core user row the guide never provisioned. A
  new RLS-safe seed helper (`scripts/seed_local_user.py`) is shared by the
  installer and the manual guide, and the pre-seed failure mode is documented.
- The documented backup dump role could not dump this schema at all: every
  relevant table carries forced row-level security, and `pg_dump` aborts rather
  than emit a partial dump. The runbook now prescribes a role model that works
  and discloses its tradeoffs.
- The restore drill could not pass under a least-privilege admin because dumps
  carried extension comments only an owner may restore. Dumps are now
  comment-free, and drill failures surface their real diagnostics without
  contaminating sanitized receipts.
- Migration `0093` now brackets its repair work so it completes under an admin
  role without `BYPASSRLS`. No published release contains the prior body, and
  already-migrated databases are byte-identical in end state.
- Documented secret paths moved from boot-volatile locations to persistent
  ones, so scheduled jobs survive a reboot.

The class fix behind all of this: the full-history ops CI lane now provisions
distinct root, admin, app, backup, and lifecycle roles, with an admin that is
neither superuser nor `BYPASSRLS`. Four of the five defects were invisible to a
superuser-admin CI and cannot regress silently again.

## Operational evidence, executed rather than asserted

Backup, destroy-restore, portable export and import, upgrade from v0.12 to
current, health, and monitoring evidence ran on both SQLite and PostgreSQL 16
backends, producing sanitized receipts. The scheduler ships with all workflows
disabled by default; on-demand operation is a documented, legitimate posture.

## Browser clip capability

The browser clipper now uses a short-lived, origin-bound, one-time capability:
the raw value is never stored, cannot be replayed, and is rejected cross-origin.

## Security posture

This release's security basis is automated security scanning and internal
adversarial review, findings triaged and fixed. Aggregate CodeQL alerts were
cleared without suppressions. This release is not independently audited and not
penetration tested, and no compliance certification is claimed.

## Compatibility

- Both governed versions move 0.13.1 to 0.14.0; no store schema change beyond
  the Phase 5 additive migrations already described above.
- No retrieval, ranking, or memory-behavior change.
- The legacy `/v0` compatibility routers remain unmounted in production
  (`ALICE_LEGACY_SURFACES=0`, `LEGACY_V0_ENABLED_OUTSIDE_DEV=false`).
- Remote `/v1` remains unsupported; workspace bootstrap and provider
  administration stay loopback-only operator actions.
