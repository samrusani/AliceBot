# Alice v0.9.3 Release Notes

`v0.9.3` is a security and reliability hotfix over `v0.9.2`. It fixes five
P1 correctness defects an external audit found in the released code. Each
fix was written reproduction-first: the audit's exact failing scenario was
turned into a test that failed on the pre-fix code and passes now.

## Fixes

- **Lifecycle state machine.** All memory lifecycle mutations — confirm,
  review, correct, undo, forget, expire/unexpire, supersession — now route
  through one central transition table (`vnext_lifecycle`) that rejects
  invalid transitions. A rejected or superseded row can no longer be
  confirmed back to `active`; `correct()` no longer promotes rows while
  leaving them unconfirmed and review-required; supersession `A → B → A`
  cycles are blocked; and `unexpire` can no longer report `active` while the
  stored row remains stale.
- **Expire/unexpire races.** These operations now lock the row before policy
  evaluation, so a concurrent correction or supersession can no longer be
  overwritten by a stale snapshot.
- **Migration identifier stranding.** Migration `20260711_0083` could reserve
  retry/confirmation identifiers on a deleted tombstone, leaving the live row
  unfindable and the identifier unusable. Deduplication now prefers the
  active row, and a corrective migration `20260712_0084` repairs databases
  already mis-upgraded by v0.9.2 (both PostgreSQL and SQLite). `0083` is left
  unchanged; `0084` is idempotent and its downgrade is a no-op.
- **Project-scoped capture.** A project-scoped agent's captured memory now
  persists its effective scope, so the owning project can retrieve it and
  other projects are excluded. Previously the scope was validated but never
  stored.
- **Hard people/time filters.** The retriever now over-fetches (bounded) when
  people/time filters are set, so a valid scoped row ranked behind a full
  window of non-matching candidates is still surfaced instead of returning an
  empty pack.

## Upgrade

`alembic upgrade head` applies migration `0084` (idempotent; safe to re-run).
SQLite databases correct themselves on next open. No operator action beyond
running migrations. Databases mis-upgraded by v0.9.2's `0083` are repaired
automatically.

## Verifying this release

The wheel and source distribution are published to PyPI through GitHub
Trusted Publishing and carry PyPI's integrity attestations, which bind each
file to this repository, the `v0.9.3` tag, the publishing workflow, the exact
commit, the release event, and the protected `pypi` environment — verifiable
on the project's PyPI page. The exact SHA-256 digests of the published
artifacts are recorded in `docs/release/v0.9.3-checksums.txt` in this
repository as part of the post-publication commit.

## Not included

This hotfix is scoped to the five user-facing correctness defects. Further
audit items — embedding vector-space fingerprinting, consolidation and
roll-up membership at scale, a vector-enabled release-eval gate, and the P2
list — are tracked for the next cycle and gate the resumption of `v0.10.0`
feature work.
