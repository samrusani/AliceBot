# Alice v0.12.0 Release Notes
<!-- alice-release-state: {"schema_version":"alice_release_document_state_v1","version":"0.12.0","publication_status":"pending","checksums_status":"pending"} -->

**Structure only. Zero behavior change.**

`v0.12.0` reorganizes the codebase and changes no behavior. Every externally
observable surface — HTTP routes and their OpenAPI document, the MCP tool
registry, the CLI command tree, error contracts, and generated SQL — is
verified identical to the published `v0.11.1`.

## Structural moves

- HTTP handlers move from the former `main.py` monolith (12,856 lines) into
  fourteen domain routers behind a compact application assembly;
  `alicebot_api.main:app` remains the stable application import.
- PostgreSQL and SQLite vNext store seams move in corresponding pairs behind
  stable facades, so the two backends correspond file-for-file. Surviving
  legacy-store code and pure contracts move into domain modules behind their
  existing public imports.
- MCP registry/dispatch and tools move into `alicebot_api.mcp`; the
  `mcp_tools.py` facade remains compatible.
- CLI parser/dispatch and commands move into `alicebot_api.cli`; the `alice`,
  `alicebot`, and `alice-memory` console entrypoints remain unchanged.
- No production Python file exceeds 4,000 lines; `main.py` is 1,140 lines and
  the largest production Python file is 3,803 lines.

## Preserved contracts

- The OpenAPI document is byte-identical to `v0.11.1` in both the default
  (182 operations) and legacy-flag (231 operations) postures. Route paths,
  operation IDs, dependencies, error behavior, and conditional legacy
  mounting are unchanged.
- All 76 MCP tool definitions are byte-identical: 11 core, 65 legacy, with
  the same gating, agent-key suppression, aliases, and error contracts.
- PostgreSQL and SQLite store protocols, method signatures, ordering,
  generated SQL text, and migration history are unchanged; the pinned
  SQL-shape tests pass without edits.
- CLI parser topology, handler routing, help text, public namespace, and
  entrypoints remain unchanged.
- Six narrow internal adaptations forced by the split (Python-level
  introspection shapes such as lazy router objects, a route-matching helper,
  and CLI parser nesting depth) are documented in the Phase 3 handoff record
  and were owner-ratified. None is observable at the HTTP, MCP, or CLI
  surface.

## Gates strengthened in the move

- Public-response hygiene enforcement scans every router module with a
  296-call per-module manifest and taint propagation for delayed
  exception-text flows.
- Coverage enforcement follows the fourteen-router aggregate at the same
  threshold that previously applied to the monolith.
- The default-surface PostgreSQL smoke requires a nonzero executed-test
  count, and namespace/registry guards fail on the old monolith shape.

## Candidate verification

The reviewed carrier passed 3,804 unit tests (80.38% package coverage), 399
role-separated PostgreSQL integration tests with one expected skip plus the
executed flag-off default-surface smoke, 127 LongMemEval tests, and the full
web matrix — independently reproduced by the release engineer on the exact
tree before this release was cut.

## Upgrade

No migrations; `alembic` head is unchanged from `v0.11.1`. No operator
action. Code that imports Alice's internal module paths directly (rather
than the documented facades) may need import updates; all documented entry
points — `alicebot_api.main:app`, the console commands, and the MCP server
module — are unchanged.

## Verifying this release

Alice publishes to PyPI through GitHub Trusted Publishing. The published
wheel and source distribution carry PyPI's integrity attestations, which
bind each file to this repository, the release tag, the publishing workflow,
the exact commit, and the protected `pypi` environment — verifiable on the
project's PyPI page. Their exact SHA-256 digests are recorded in
`docs/release/v0.12.0-checksums.txt` in this repository.
